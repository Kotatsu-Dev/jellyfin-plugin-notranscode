# jellyfin-plugin-notranscode

Снимает настройки перекодирования у пользователей, оставляя только Direct Play (воспроизведение без перекодирования).

В Jellyfin нет шаблона политики для новых пользователей: настройку «Allow video playback that
requires transcoding» приходится снимать вручную каждому отдельно. Плагин закрывает
этот пробел — держит настройку отключенной у существующих и новых пользователей.

У пользователя со отключенным видео-транскодом пропадает
выпадающий список выбора битрейта в плеере — сервер перестаёт предлагать пониженные варианты качества
в `PlaybackInfo`, избавляя сервер от возможной нагрузки.

Требуется Jellyfin 12.0.

## Установка

Dashboard → Plugins → Repositories → **+**, добавить репозиторий:

```
https://raw.githubusercontent.com/Kotatsu-Dev/jellyfin-plugin-notranscode/master/manifest.json
```

Затем Dashboard → Plugins → Catalog → **No Transcode** → Install и рестарт сервера.

## Что делает

Выставляет в `UserPolicy`:

| Флаг                                | По умолчанию | Почему                                                        |
|-------------------------------------|--------------|---------------------------------------------------------------|
| `EnableVideoPlaybackTranscoding`    | снимается    | даёт основную нагрузку на CPU/GPU                             |
| `EnableAudioPlaybackTranscoding`    | не трогается | аудио в форматах AC3/DTS/TrueHD перестанут играть в браузере  |
| `EnablePlaybackRemuxing`            | не трогается | remux меняет только контейнер и почти не даёт нагрузки        |

Каждый флаг меняется отдельным чекбоксом на странице настроек плагина. Там же —
«Применять ко всем при старте», «Применять к новым пользователям» и «Не трогать
администраторов».

## Принцип работы

* `PolicyApplier` — общая логика. Читает текущую политику через `IUserManager.GetUserDto`,
  снимает разрешённые к снятию флаги и вызывает `UpdatePolicyAsync` **только если**
  что-то реально изменилось. Повторный рестарт сервера не пишет в лог те же строки
  второй раз и не генерирует лишние события обновления пользователя.
* `PolicyEnforcer` — `IHostedService`, стартовый проход по `IUserManager.GetUsers()`.
  Запускается после миграций базы, когда пользователи уже доступны. Исключения логируются:
  сбой плагина не должен ронять сервер.
* `UserCreatedConsumer` — `IEventConsumer<UserCreatedEventArgs>`. В Jellyfin 12 у
  `IUserManager` нет события `OnUserCreated`; `UserManager.CreateUserAsync` публикует
  `UserCreatedEventArgs` через `IEventManager`, а тот резолвит консьюмеров из отдельного
  DI-scope. Поэтому консьюмер регистрируется как `AddScoped`.

## Что плагин НЕ делает

Не блокирует транскод на уровне сервера — только выставляет те же пользовательские флаги,
что и в Dashboard → Users → Media Playback. Админ сервера по-прежнему может
вернуть флаг вручную; при следующем рестарте сервера плагин снимет её обратно
(если включено «Применять ко всем при старте»).
