# jellyfin-plugin-notranscode

Снимает флаги перекодирования в политике пользователей, оставляя только Direct Play.

В Jellyfin нет шаблона политики для новых аккаунтов: флаг «Allow video playback that
requires transcoding» приходится снимать вручную каждому пользователю. Плагин закрывает
этот пробел — держит флаги снятыми и у существующих пользователей, и у всех вновь
созданных.

Побочный эффект: у пользователя со снятым флагом видео-транскода из плеера пропадает
выпадающий список выбора битрейта — сервер перестаёт предлагать пониженные варианты
в `PlaybackInfo`.

Требуется Jellyfin 12.0.

## Установка

Dashboard → Plugins → Repositories → **+**, добавить репозиторий:

```
https://raw.githubusercontent.com/Kotatsu-Dev/jellyfin-plugin-notranscode/master/manifest.json
```

Затем Dashboard → Plugins → Catalog → **No Transcode** → Install и рестарт сервера.

## Что делает

Выставляет в `UserPolicy`:

| Флаг                                | По умолчанию | Почему                                                        |
|-------------------------------------|--------------|---------------------------------------------------------------|
| `EnableVideoPlaybackTranscoding`    | снимается    | основная нагрузка на CPU/GPU                                   |
| `EnableAudioPlaybackTranscoding`    | не трогается | иначе дорожки AC3/DTS/TrueHD перестанут играть в браузере      |
| `EnablePlaybackRemuxing`            | не трогается | remux меняет только контейнер и почти бесплатен                |

Каждый флаг переключается отдельной галочкой на странице настроек плагина. Там же —
«Применять ко всем при старте», «Применять к новым пользователям» и «Не трогать
администраторов».

## Принцип работы

* `PolicyApplier` — общая логика. Читает текущую политику через `IUserManager.GetUserDto`,
  снимает разрешённые к снятию флаги и вызывает `UpdatePolicyAsync` **только если**
  что-то реально изменилось. Из-за этой проверки повторный рестарт сервера не пишет
  в лог те же строки второй раз и не плодит лишних событий обновления пользователя.
* `PolicyEnforcer` — `IHostedService`, стартовый проход по `IUserManager.GetUsers()`.
  Запускается после миграций базы, так что пользователи уже доступны. Исключения
  проглатываются и логируются: сбой плагина не должен ронять сервер.
* `UserCreatedConsumer` — `IEventConsumer<UserCreatedEventArgs>`. В Jellyfin 12 у
  `IUserManager` нет события `OnUserCreated`; `UserManager.CreateUserAsync` публикует
  `UserCreatedEventArgs` через `IEventManager`, а тот резолвит консьюмеров из отдельного
  DI-scope. Поэтому консьюмер регистрируется как `AddScoped`.

## Что плагин НЕ делает

Не блокирует транскод на уровне сервера — он только выставляет пользовательские флаги,
те же, что руками ставятся в Dashboard → Users → Media Playback. Админ по-прежнему может
вернуть галочку вручную; при следующем рестарте сервера плагин снимет её обратно
(если включено «Применять ко всем при старте»).
